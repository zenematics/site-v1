# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the built `dist/`

There are no tests or linters configured.

## Architecture

Static React 19 + Vite multi-page site (no router library) for Zenematics and its Zenderal modlist (an Enderal SE modlist). Deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`.

### Pages / entry points

Each page is a separate HTML entry registered in `vite.config.js` `rollupOptions.input`; adding a page means adding an HTML file there plus an entry script:

| URL | HTML | Entry script | Page component |
| --- | --- | --- | --- |
| `/` | `index.html` | `src/main.jsx` | `src/pages/Home.jsx` |
| `/zenderal/` | `zenderal/index.html` | `src/zenderal.jsx` | `src/pages/Zenderal.jsx` (overview) |
| `/zenderal/docs/` | `zenderal/docs/index.html` | `src/zenderal-docs.jsx` | `src/pages/ZenderalDocs.jsx` |
| `/zenderal/guide/` | `zenderal/guide/index.html` | `src/zenderal-guide.jsx` | `src/pages/ZenderalGuide.jsx` (guide overview) |
| `/zenderal/guide/<id>/` | `zenderal/guide/<id>/index.html` (generated) | `src/zenderal-guide.jsx` | `src/pages/ZenderalGuide.jsx` (one guide section) |

Each HTML file carries its own `<title>`, description and Open Graph/Twitter tags (link previews). Their URLs are absolute on `https://zenematics.com` (the Pages custom domain), and the share images are `public/uploads/og/zenematics.jpg` (home) and `og/zenderal.jpg` (all `/zenderal/` pages), both 1200×630.

The home page renders `src/components/Hero.jsx` (the hover accordion) on desktop and tablet and `src/components/MobileHero.jsx` (a vertical tap accordion on one screen) below 760px wide; `Home.jsx` picks one. Changes to one don't carry over to the other.

Each guide section is its own page. The list (id, title, group, `desc`) is `SECTIONS` in `src/zenderal/guide/sections.js` (plain JS so node can import it); `npm run gen:guide` writes `zenderal/guide/<id>/index.html` for each, with its title/preview tags and `data-section="<id>"` on `#root`, and `vite.config.js` registers every folder under `zenderal/guide/` as an entry. All guide pages share one entry; `ZenderalGuide.jsx` renders the overview (cards per group) when there's no section, and lazy-loads the section's component otherwise. The overview redirects old `#<section-id>` links (and `SECTION_ALIASES`) to the new pages. Adding a section: add it to `SECTIONS` and `BODY`, then run `gen:guide`. Its sections live in `src/zenderal/guide/` (one component each, plus Perk Trees from `src/zenderal/`; Controller Support uses `src/zenderal/Gamepad.jsx`) and all their data (races, affinities, firearms, armor sets, For Honor Reforged, keybindings) is in `src/zenderal/guide/data.js`, taken from the list's winning plugin records. Its Magic section lists the spell vendors (`VENDORS` in `data.js`, each stock line matched against `spells.json`'s `source`/`tier`/`school`/`archetype`); FHR status icons are in `public/uploads/guide/fhr/`. Prophecy Talents (`Prophecy.jsx`, with the interactive radial map and build planner in `ProphecyMap.jsx`) reads `src/zenderal/guide/prophecy.js`, including each talent's radial-map position, generated once from zenderal-patches' `src/ProphecyV3/data/SKSE/Plugins/ZenProphecyUI.json` (no import script yet); its art and the trait icons are WebP conversions in `public/uploads/guide/prophecy/` and `public/uploads/guide/traits/`.

The docs page uses hash routing (`#<doc-id>`, `#<doc-id>/<section>` for docs listed in `docSections`) parsed in `readHash()`, which also redirects the old `#spells`/`#perks`/`#controller` links to the guide. `src/zenderal/Sidebar.jsx` is used by the docs page (it switches docs in place via `onPick`/`onPickSection`); the overview page has no sidebar.

### Base path

GitHub Pages serves under `/<repo>/`, so the deploy sets `BASE_PATH` and Vite's `base`. Internal links and asset URLs in JSX must be built from `import.meta.env.BASE_URL` (e.g. `` `${import.meta.env.BASE_URL}uploads/foo.png` ``), never hard-coded absolute paths. Static assets live in `public/uploads/`.

### Content

- **Markdown content** lives in `content/zenderal/` and is loaded at build time by `src/zenderal/content.js` via `import.meta.glob(..., { query: '?raw', eager: true })` with a minimal hand-rolled frontmatter parser (`key: value` lines only). The file header comment there documents what each file maps to.
- `## ` headings of the docs in `docSections` (`content.js`; readme, render-pipeline and performance) become sidebar sub-links; `slugify` in `content.js` must stay shared between `Md.jsx` (heading ids) and the sidebar.
- **Spells** (`content/zenderal/spells.json`, read by the guide's Magic section; the old `#spells` link lands there) is generated by `npm run import:spells [path]` from the MagicExtract `spells.json` in the sibling `zenderal-patches/arch-docs/magic/data/` repo. Only tome-taught spells are kept; `sourceOf()` in the script maps plugins to the spell packs. Import from zenderal-patches' `main` (e.g. `git -C ../zenderal-patches show origin/main:arch-docs/magic/data/spells.json > tmp.json`, then pass that path): the sibling checkout may be on another branch with an older extract, and importing that silently reverts Zenderal's spell re-schooling.
- **Perk Trees** (guide `#perks`, `src/zenderal/Perks.jsx`) reads `content/zenderal/perks.json`, generated by `npm run import:perks [path]` from `zenderal-patches/arch-docs/perks/perks.json`. Star x/y are the in-game memory-star positions projected onto each wall; the importer swaps EGO's German titles for base Enderal's English ones (`GERMAN` regex) and adds the class root talent under each tree.
- **Structured data** (doc list/groups, controller layout for `Gamepad.jsx`, FAQ, the overview page's intro and its link cards in `OVERVIEW.explore`) is in `src/zenderal/data.js`. Adding a doc to `DOCS` also requires rendering it in `ZenderalDocs.jsx`.
- **Site config** in `src/config.js`: Zenderal release stage, social links, and YouTube IDs for the home hero panel videos.

### Styling and fonts

Plain CSS: `src/index.css` (global + home) and `src/zenderal.css` (Zenderal pages), BEM-ish class names. Futura PT is loaded from Adobe Fonts using `VITE_TYPEKIT_ID`, substituted into each HTML file via `%VITE_TYPEKIT_ID%` — set locally in `.env` (gitignored) and in CI via the repo variable `vars.VITE_TYPEKIT_ID`.

### AI-generated assets (Higgsfield / Artlist connector)

Some Zenderal visuals were made with the Higgsfield (Artlist) MCP connector. Always quote the cost with `get_generation_cost` and get the user's explicit OK before generating — credits are real money.

- **Style kit "Zenderal"** (find it with `list_style_kits`): the site palette (Void `#07080a`, Night `#0d0e11`, Slate `#17181c`, Bone `#ece9e2`, Ash `#c9c5bd`, Stone `#9b968d`, Dust `#6f6a62`, Muted gold `#c9ab76`, Cold blue `#7fa7c9`), a "Treatment" guideline (dark fantasy, painterly realism, desaturated with muted gold highlights, cold blue only as an accent, keep the input image's location and lighting) and an "Exclusions" guideline (no text/logos/sigils, nothing modern, no saturated or neon colours). Pass it as `styleKitId` for any Zenderal image or video. It also holds nine trait illustrations ("Trait art: …", from `public/uploads/guide/traits/`) and a "Drawn art style" guideline for illustrated art in the style of Enderal's trait/Prophecy graphics; whole-kit generations pull those images in, so for screenshot or photo edits narrow it with `styleKitItemIds` to the palette, Treatment and Exclusions, and for drawn art use the palette, the trait images and the drawn style (drop Exclusions if the subject is modern, e.g. the guide's keyboard/controller cards).
- **3D emblem** (`public/uploads/zenderal-emblem.glb`, ~1.8 MB): image-to-3D from the flat emblem, then hand-fixed (spiked arc moved in line with and slightly in front of the sphere, body tilted so the bottom point faces straight down) and optimised with `@gltf-transform` (simplify to ~72k tris, meshopt). sharp/libvips is broken on this machine, so textures are converted to WebP with ffmpeg instead (normal map 2048, others 1024). The model node is rotated 90° about X, so in raw vertex positions up is −Z and depth is +Y. Rendered by `src/zenderal/emblem3d.js` (three.js, lazy-loaded by `Emblem.jsx` with `live`; the flat WebP shows for reduced motion and until the model loads). Shown in the nav on the Zenderal pages (`Nav.jsx`, linking to the overview); the overview hero dropped it for a full-width, centred wordmark, and the home page keeps the flat image (the 3D version was tried there and rejected).
- **Growing-vines logo** (`public/uploads/zenderal/logo-grow.webm`/`.mp4`): an image-to-video from an AI start frame (the Z alone, prompted to keep its exact strokes) to `logo-white.png` as the end frame. It is white on black and overlaid with `mix-blend-mode: screen`; `Logo.jsx` plays it once then swaps to the PNG, which matches the last frame. It is also the home page's Zenderal panel video (`PanelLogo` in `Hero.jsx`, replayed each time the panel opens). Re-encodes must keep the same crop/size as the PNG and crush the blacks to pure black.
- **Parallax backdrops** (`public/uploads/zenderal/hero/ark-*.webp`, `public/uploads/zenderal/layers/<name>-back/mid/front.webp`): a screenshot split into depth layers with Seedream 5 Pro Layerize, then rebuilt on the original: each cut-out is located on the screenshot by a brute-force scale/offset search, visible pixels keep the screenshot's colours, and only the parts hidden at rest use AI pixels (colour-matched) or a fill from the surrounding pixels. The layerize "clean plate" outputs are repainted and don't line up, so don't rely on them. The intro uses `layers/river`; `layers/crystal` backs the closing "Ready to play?" section, pushed right of the text and desaturated towards the site palette. Ideas for AI visuals from the old goals list are in Jira WD-106 to WD-110. The intro sits over the hero and fades in at its top (`--blend`); its text is outside that mask so it can start inside the fade and peek above the fold. At its end it pins and closes into the emblem: `emblem-mask.png` (the emblem art's alpha with enclosed holes filled) masks the scene while the flat emblem art fades in over it (`Zenderal.jsx`; reduced motion keeps a plain fade). The closing section does the same in reverse with the Zenematics mark (`zen-logo-white.png`'s alpha as the mask): it pins, the white mark fades as the scene shows through it, and it grows until the head (`ZEN`, its largest solid circle) covers the screen, then the text fades in. It rests as far below the cards as the emblem does above them, so its margin is computed and the pin overlaps the end of the cards (it only takes clicks on its text).
- Check visual changes with headless `puppeteer-core` driving the system Chrome (`--use-angle=swiftshader` so WebGL works) when the Chrome extension is unavailable.

Images: photo/screenshot backgrounds are WebP (~2560px wide, quality 85 — lower bands the dark gradients); hero backgrounds live in `public/uploads/zenderal/screenshots/backgrounds/`.
