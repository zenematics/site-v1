# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the built `dist/`

There are no tests or linters configured.

## Architecture

Static React 19 + Vite multi-page site (no router library) for Zenematics and its Zenderal modlist (an Enderal SE modlist). Deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`.

### Pages / entry points

Each page is a separate HTML entry registered in `vite.config.js` `rollupOptions.input`; adding a page means adding an HTML file there plus an entry script:

| URL | HTML | Entry script | Page component |
| --- | --- | --- | --- |
| `/` | `index.html` | `src/main.jsx` | `src/pages/Home.jsx` |
| `/zenderal/` | `zenderal/index.html` | `src/zenderal.jsx` | `src/pages/Zenderal.jsx` (overview) |
| `/zenderal/docs/` | `zenderal/docs/index.html` | `src/zenderal-docs.jsx` | `src/pages/ZenderalDocs.jsx` |
| `/zenderal/guide/` | `zenderal/guide/index.html` | `src/zenderal-guide.jsx` | `src/pages/ZenderalGuide.jsx` (guide overview) |
| `/zenderal/guide/<id>/` | `zenderal/guide/<id>/index.html` (generated) | `src/zenderal-guide.jsx` | `src/pages/ZenderalGuide.jsx` (one guide section) |

Each HTML file carries its own `<title>`, description and Open Graph/Twitter tags (link previews). Their URLs are absolute on `https://zenematics.com` (the Pages custom domain), and the share images are `public/uploads/og/zenematics.jpg` (home) and `og/zenderal.jpg` (all `/zenderal/` pages), both 1200×630.

The home page renders `src/components/Hero.jsx` (the hover accordion) on desktop and tablet and `src/components/MobileHero.jsx` (a vertical tap accordion on one screen) below 760px wide; `Home.jsx` picks one. Changes to one don't carry over to the other.

Each guide section is its own page. The list (id, title, group, `desc`) is `SECTIONS` in `src/zenderal/guide/sections.js` (plain JS so node can import it); `npm run gen:guide` writes `zenderal/guide/<id>/index.html` for each, with its title/preview tags and `data-section="<id>"` on `#root`, and `vite.config.js` registers every folder under `zenderal/guide/` as an entry. All guide pages share one entry; `ZenderalGuide.jsx` renders the overview (cards per group) when there's no section, and lazy-loads the section's component otherwise. The overview redirects old `#<section-id>` links (and `SECTION_ALIASES`) to the new pages. Adding a section: add it to `SECTIONS` and `BODY`, then run `gen:guide`. Its sections live in `src/zenderal/guide/` (one component each, plus Perk Trees from `src/zenderal/`; Controller Support uses `src/zenderal/Gamepad.jsx`) and all their data (races, affinities, firearms, armor sets, For Honor Reforged, keybindings) is in `src/zenderal/guide/data.js`, taken from the list's winning plugin records. Unique Armor (`ArmorSets.jsx`) shows each set rendered as worn (`public/uploads/guide/armor/`, Blender + PyNifly renders of the list's winning meshes) and pops up Enderal's paper world map (`public/uploads/guide/vyn-map.webp`, from `textures\map\enderal_main.dds`) with the spot marked when a location is hovered or tapped; the points are in the generated `armormap.js`. Its Magic section lists the spell vendors (`VENDORS` in `data.js`, each stock line matched against `spells.json`'s `source`/`tier`/`school`/`archetype`); FHR status icons are in `public/uploads/guide/fhr/`. Prophecy Talents (`Prophecy.jsx`, with the interactive radial map and build planner in `ProphecyMap.jsx`; where the trees, their names and the lines between the stars (`EDGES`) sit is in `prophecyLayout.js`, shared with the overview's build-crafting section, which zooms into `screenshots/perks-overview.webp`'s stone circle, turns a ring of the trait icons round it (stopping on `OVERVIEW.build.traits`), then opens into the radial art, with a chapter rail of `OVERVIEW.build.stages` beside it) reads `src/zenderal/guide/prophecy.js`, including each talent's radial-map position, generated from the installed list's `ZenProphecyUI.json` (MO2 mod `Zenderal - Prophecy v3 (Constellation)`, built from zenderal-patches' `src/ProphecyV3/`, whose working tree is often ahead of any branch; no import script in this repo yet). Its art and the trait icons are WebP conversions in `public/uploads/guide/prophecy/` and `public/uploads/guide/traits/` (talents from the mod's `interface/ProphecyPics/*.dds`; trees without a banner `.webp` get a colour wash). The guide card and header use `trees/radial-map.webp`, a still of the radial art with the map's lines and stars drawn on (rendered in headless Chrome from `prophecyLayout.js`; re-render it if the layout changes). The map places tree names itself, since the game's label spots overlap the stars; the Rage and Darkness gauge text in `Prophecy.jsx` follows `ZenProphecyRage.json` / `ZenProphecyDarkness.json` in the same mod.

The docs page uses hash routing (`#<doc-id>`, `#<doc-id>/<section>` for docs listed in `docSections`) parsed in `readHash()`, which also redirects the old `#spells`/`#perks`/`#controller` links to the guide. `src/zenderal/Sidebar.jsx` is used by the docs page (it switches docs in place via `onPick`/`onPickSection`); the overview page has no sidebar.

### Base path

GitHub Pages serves under `/<repo>/`, so the deploy sets `BASE_PATH` and Vite's `base`. Internal links and asset URLs in JSX must be built from `import.meta.env.BASE_URL` (e.g. `` `${import.meta.env.BASE_URL}uploads/foo.png` ``), never hard-coded absolute paths. Static assets live in `public/uploads/`.

### Content

- **Markdown content** lives in `content/zenderal/` and is loaded at build time by `src/zenderal/content.js` via `import.meta.glob(..., { query: '?raw', eager: true })` with a minimal hand-rolled frontmatter parser (`key: value` lines only). The file header comment there documents what each file maps to.
- `Md.jsx` adds two conventions: a `#### ` heading starts a fold-out (`<details>`, up to the next heading of level 4 or above or a `---`), used for troubleshooting entries; and a GFM task list (`- [ ] **Title**` then the text on the next line) renders as numbered checklist cards the reader can tick, saved in localStorage (the readme's Before you install). A run of `##### ` headings becomes tabs with big buttons (a heading that's just an image shows it, e.g. the Performance page's NVIDIA / AMD / Intel logos); each tab runs to the next `#####`, a heading of level 4 or above or a `---`, the pick is saved in localStorage, and with none saved the GPU the browser reports through WebGL preselects its tab. An image followed by an italic-only line gets that line as its caption. `<Md sections>` (the Performance doc) makes each `## ` section a closed drop-down with its heading as the button; the docs page opens one when a sidebar or in-page link points into it. A line that's only bold text is a small label (`md-label`). A paragraph starting "Press `Key`" becomes a key callout with a big keycap (the Performance page's "Press `End` to open Theo's mod menu"), and a bracketed part of a table header drops to a smaller note under it. `## ` headings and checklist steps get line icons from `src/zenderal/DocIcons.jsx` (`HEADING_ICONS` by heading id, `stepIcon` by step title); brand logos for tables are Simple Icons SVGs (CC0) in `public/uploads/brands/`, coloured and cropped to the mark.
- `## ` headings of the docs in `docSections` (`content.js`; readme, render-pipeline and performance) become sidebar sub-links; `slugify` in `content.js` must stay shared between `Md.jsx` (heading ids) and the sidebar.
- **Spells** (`content/zenderal/spells.json`, read by the guide's Magic section; the old `#spells` link lands there) is generated by `npm run import:spells [path]` from the MagicExtract `spells.json` in the sibling `zenderal-patches/arch-docs/magic/data/` repo. Only tome-taught spells are kept; `sourceOf()` in the script maps plugins to the spell packs. Import from zenderal-patches' `main` (e.g. `git -C ../zenderal-patches show origin/main:arch-docs/magic/data/spells.json > tmp.json`, then pass that path): the sibling checkout may be on another branch with an older extract, and importing that silently reverts Zenderal's spell re-schooling.
- **Perk Trees** (guide `#perks`, `src/zenderal/Perks.jsx`) reads `content/zenderal/perks.json`, generated by `npm run import:perks [path]` from `zenderal-patches/arch-docs/perks/perks.json`. Star x/y are the in-game memory-star positions projected onto each wall, but `symmetric()` in `Perks.jsx` only keeps their left-to-right order, placing stars in evenly spaced rows by distance from the root, spread evenly about the middle; the importer swaps EGO's German titles for base Enderal's English ones (`GERMAN` regex) and adds the class root talent under each tree.
- **Structured data** (doc list/groups, controller layout for `Gamepad.jsx`, FAQ, the overview page's before/after wipe in `OVERVIEW.compare`, its combat clips in `OVERVIEW.combat`, its expanded-magic section after the combat clips (`src/zenderal/Grimoire.jsx`: a pinned spell counter that climbs as each pack's spell names fade in, lazy-loading `spells.json` like the Magic guide), the firearms heading in `OVERVIEW.firearms` (shown under the 3D Gewehr), its build-crafting section after that (the last before the closing section) in `OVERVIEW.build`, its "What Zenderal is" section right under the hero (a crossroads image whose two roads, new to Enderal and played it before, each open a row of picture panels) in `OVERVIEW.welcome`) is in `src/zenderal/data.js`. Adding a doc to `DOCS` also requires rendering it in `ZenderalDocs.jsx`.
- **Site config** in `src/config.js`: Zenderal release stage, social links, and YouTube IDs for the home hero panel videos.

### Styling and fonts

Plain CSS: `src/index.css` (global + home) and `src/zenderal.css` (Zenderal pages), BEM-ish class names. Futura PT is loaded from Adobe Fonts using `VITE_TYPEKIT_ID`, substituted into each HTML file via `%VITE_TYPEKIT_ID%` — set locally in `.env` (gitignored) and in CI via the repo variable `vars.VITE_TYPEKIT_ID`.

### AI-generated assets (Higgsfield / Artlist connector)

Some Zenderal visuals were made with the Higgsfield (Artlist) MCP connector. Always quote the cost with `get_generation_cost` and get the user's explicit OK before generating — credits are real money.

- **Style kit "Zenderal"** (find it with `list_style_kits`): the site palette (Void `#07080a`, Night `#0d0e11`, Slate `#17181c`, Bone `#ece9e2`, Ash `#c9c5bd`, Stone `#9b968d`, Dust `#6f6a62`, Muted gold `#c9ab76`, Cold blue `#7fa7c9`), a "Treatment" guideline (dark fantasy, painterly realism, desaturated with muted gold highlights, cold blue only as an accent, keep the input image's location and lighting) and an "Exclusions" guideline (no text/logos/sigils, nothing modern, no saturated or neon colours). Pass it as `styleKitId` for any Zenderal image or video. It also holds nine trait illustrations ("Trait art: …", from `public/uploads/guide/traits/`) and a "Drawn art style" guideline for illustrated art in the style of Enderal's trait/Prophecy graphics; whole-kit generations pull those images in, so for screenshot or photo edits narrow it with `styleKitItemIds` to the palette, Treatment and Exclusions, and for drawn art use the palette, the trait images and the drawn style (drop Exclusions if the subject is modern, e.g. the guide's keyboard/controller cards). Describing the style in a prompt alone comes out too clean and too bright; what works is image-to-image with one or two trait icons (`public/uploads/guide/traits/`) uploaded as texture references, on Nano Banana 2.1 at 4K, then asking for one change per edit (e.g. "add the woven grain", then "remove the outlines") while keeping everything else. Ask for no outlines rather than "silhouettes" (that gives flat cut-outs), and check the result's brightness against the trait icons.
- **3D emblem** (`public/uploads/zenderal-emblem.glb`, ~1.8 MB): image-to-3D from the flat emblem, then hand-fixed (spiked arc moved in line with and slightly in front of the sphere, body tilted so the bottom point faces straight down) and optimised with `@gltf-transform` (simplify to ~72k tris, meshopt). sharp/libvips is broken on this machine, so textures are converted to WebP with ffmpeg instead (normal map 2048, others 1024). The model node is rotated 90° about X, so in raw vertex positions up is −Z and depth is +Y. Rendered by `src/zenderal/emblem3d.js` (three.js, lazy-loaded by `Emblem.jsx` with `live`; the flat WebP shows for reduced motion and until the model loads). Shown in the nav on the Zenderal pages (`Nav.jsx`, linking to the overview); the overview hero dropped it for a full-width, centred wordmark, and the home page keeps the flat image (the 3D version was tried there and rejected). The overview hero has its own Install/Guides/Support row (`ZenLinks hero` from `Nav.jsx`); `Nav`'s `dock` keeps the nav's copies hidden until the nav's background comes in on scrolling, then flies each one from its twin into the nav (and back on scroll up), re-measuring the twin every frame.
- **Growing-vines logo** (`public/uploads/zenderal/logo-grow.webm`/`.mp4`): an image-to-video from an AI start frame (the Z alone, prompted to keep its exact strokes) to `logo-white.png` as the end frame. It is white on black and overlaid with `mix-blend-mode: screen`; `Logo.jsx` plays it once then swaps to the PNG, which matches the last frame. It is also the home page's Zenderal panel video (`PanelLogo` in `Hero.jsx`, replayed each time the panel opens). All three are cropped to the lettering left and right (no side margins; the original 2048 PNG lost 100px left and 64px right), so the logo box is the lettering and the hero line under it is sized and capped by `--w`; the home panels size their boxes to match. Re-encodes must keep the same crop/size as the PNG and crush the blacks to pure black.
- **Parallax backdrops** (`public/uploads/zenderal/hero/ark-*.webp`, `public/uploads/zenderal/layers/<name>-back/mid/front.webp`): a screenshot split into depth layers with Seedream 5 Pro Layerize, then rebuilt on the original: each cut-out is located on the screenshot by a brute-force scale/offset search, visible pixels keep the screenshot's colours, and only the parts hidden at rest use AI pixels (colour-matched) or a fill from the surrounding pixels. The layerize "clean plate" outputs are repainted and don't line up, so don't rely on them. `layers/crossroads` is the "What Zenderal is" crossroads (back: sky, mountains and valley; mid: the village and castle cliff; front: the travellers, signpost and the near ground below the village, so they drift together); `layers/crystal` backs the closing "Ready to play?" section, pushed right of the text and desaturated towards the site palette. Ideas for AI visuals from the old goals list are in Jira WD-106 to WD-110. The "What Zenderal is" crossroads (`.znew`) is pulled up over the hero's bottom `--blend` and its scene fades in there, with its heading starting below that. It is followed by the pinned, framed "Modern visuals" before/after `.zcompare`, which opens out of the emblem: the solid emblem art sits just under the crossroads and scrolls up with the pin, then `emblem-mask.png` (the emblem art's alpha with enclosed holes filled) masks the pin while the art fades and the silhouette grows until it covers the screen; the heading fades in, and then the divider sweeps from base Enderal's shot to Zenderal's (images in `screenshots/before-and-after/`), then back left to right, wiping the section away to the combat section, pulled up to pin under it (`.zcompare + .zsword`, `WIPE` in `Zenderal.jsx`, `UNDER` in `Sword.jsx`). The sword's last swing cuts the combat section away to expanded magic in the same way (`.zclips--bare + .zmagic`, `EXIT` in `Sword.jsx`, `UNDER` in `Grimoire.jsx`), and expanded magic ends on a shot whose bullet hole cracks its middle and widens to show firearms (`.zmagic + .zmusket`, `SHOT` in `Grimoire.jsx`, `UNDER` in `Musket.jsx`); those screen counts and the CSS run heights and negative margins must change together. The mask is applied from page load so its image is ready before it shows (`Zenderal.jsx`; reduced motion keeps a plain section). The closing section does the same in reverse with the Zenematics mark (`zen-logo-white.png`'s alpha as the mask): it pins, the white mark fades as the scene shows through it, and it grows until the head (`ZEN`, its largest solid circle) covers the screen, then the text fades in. Its mark rests a fixed gap (`GAP`) below the build-crafting section (the last thing before it), so its margin is computed and the pin overlaps the end of that section (it only takes clicks on its text).
- **3D Gewehr** (`public/uploads/zenderal/gewehr.glb`, not AI): Ordo Legionis' "Double-barrel Flintlock Gewehr with dragonbone stock" (record `OL_Doublebarrel_Rifle02`, which uses mesh `ol_doublebarrelrifle03_animated.nif`, not 02), exported from its NIF to OBJ with NifSkope and built into a GLB with `@gltf-transform` (meshopt, WebP textures at 2048, the occlusion/roughness/metallic maps packed into one at 1024, the DirectX normal map's green flipped, OBJ UVs' v flipped). Its textures are the `darkwave_*` set; it has no metallic or occlusion map of its own, so those come from the `doubleriflewhite_*` set, which shares the UV layout. The mesh's barrel runs along z (muzzle towards -z, y up); NifSkope exports of other guns can come out on other axes (the blunderbuss's barrel ran along y, lock towards -z), so check the orientation in `musket3d.js` when swapping models. Rendered by `src/zenderal/musket3d.js`, lazy-loaded by `Musket.jsx`, which opens the firearms section: it starts standing upright as the I of the FIREARMS label (the `.zmusket__i` glyph is hidden until it leaves; `stand`/`sx`/`sy`/`sh` in `musket3d.js`, sized from `CAP`/`CAP_MID` in `Musket.jsx`), tips forward out of the word to aim at the viewer as the I fades in, then swings round to lie level as the heading fades in, then fires once (recoil and a muzzle flash placed from `musket3d.js`'s `muzzle()`, which finds the muzzle from the mesh so any gun works). The whiteout after the shot is fixed over the page; build crafting is pulled up behind the end of the run (`.zmusket + .zbuild`'s negative margin, tied to `WHITE` in `Musket.jsx` and the run's height) and hidden until the white is full, so it is already pinned when the white thins and is revealed in place. It must stay the section right after the gun. The gun only redraws when its pose changes. The section has no clips.
- Check visual changes with headless `puppeteer-core` driving the system Chrome (`--use-angle=swiftshader` so WebGL works) when the Chrome extension is unavailable.

Images: photo/screenshot backgrounds are WebP (~2560px wide, quality 85 — lower bands the dark gradients); hero backgrounds live in `public/uploads/zenderal/screenshots/backgrounds/`.
