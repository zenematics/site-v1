# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — production build to `dist/`
- `npm run preview` — serve the built `dist/`

There are no tests or linters configured.

## Architecture

Static React 19 + Vite multi-page site (no router library) for Zenematics and its Zenderal modlist (an Enderal SE modlist). Deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`.

### Pages / entry points

Each page is a separate HTML entry registered in `vite.config.js` `rollupOptions.input`; adding a page means adding an HTML file there plus an entry script:

| URL | HTML | Entry script | Page component |
| --- | --- | --- | --- |
| `/` | `index.html` | `src/main.jsx` | `src/pages/Home.jsx` |
| `/zenderal/` | `zenderal/index.html` | `src/zenderal.jsx` | `src/pages/Zenderal.jsx` (overview) |
| `/zenderal/docs/` | `zenderal/docs/index.html` | `src/zenderal-docs.jsx` | `src/pages/ZenderalDocs.jsx` |
| `/zenderal/guide/` | `zenderal/guide/index.html` | `src/zenderal-guide.jsx` | `src/pages/ZenderalGuide.jsx` (gameplay guide) |

The guide page uses hash routing (`#<section-id>`). Its sections live in `src/zenderal/guide/` (one component each, plus Spells and Perk Trees from `src/zenderal/`) and all their data (races, affinities, firearms, armor sets, For Honor Reforged, keybindings) is in `src/zenderal/guide/data.js`, taken from the list's winning plugin records. Its Magic section reads `spells.json`'s `tier`/`archetype` fields; FHR status icons are in `public/uploads/guide/fhr/`.

The docs page uses hash routing (`#<doc-id>`, `#<doc-id>/<section>` for docs listed in `docSections`) parsed in `readHash()`, which also redirects the old `#spells`/`#perks` links to the guide. `src/zenderal/Sidebar.jsx` is used by the docs page (it switches docs in place via `onPick`/`onPickSection`); the overview page has no sidebar.

### Base path

GitHub Pages serves under `/<repo>/`, so the deploy sets `BASE_PATH` and Vite's `base`. Internal links and asset URLs in JSX must be built from `import.meta.env.BASE_URL` (e.g. `` `${import.meta.env.BASE_URL}uploads/foo.png` ``), never hard-coded absolute paths. Static assets live in `public/uploads/`.

### Content

- **Markdown content** lives in `content/zenderal/` and is loaded at build time by `src/zenderal/content.js` via `import.meta.glob(..., { query: '?raw', eager: true })` with a minimal hand-rolled frontmatter parser (`key: value` lines only). The file header comment there documents what each file maps to.
- `## ` headings of the docs in `docSections` (`content.js`; readme and render-pipeline) become sidebar sub-links; `slugify` in `content.js` must stay shared between `Md.jsx` (heading ids) and the sidebar.
- **Spells** (guide `#spells`, `src/zenderal/Spells.jsx`) reads `content/zenderal/spells.json`, generated by `npm run import:spells [path]` from the MagicExtract `spells.json` in the sibling `zenderal-patches/arch-docs/magic/data/` repo. Only tome-taught spells are kept; `sourceOf()` in the script maps plugins to the Source filter.
- **Perk Trees** (guide `#perks`, `src/zenderal/Perks.jsx`) reads `content/zenderal/perks.json`, generated by `npm run import:perks [path]` from `zenderal-patches/arch-docs/perks/perks.json`. Star x/y are the in-game memory-star positions projected onto each wall; the importer swaps EGO's German titles for base Enderal's English ones (`GERMAN` regex) and adds the class root talent under each tree.
- **Structured data** (doc list/groups, controller setup, FAQ, the overview page's intro and goals) is in `src/zenderal/data.js`. Overview screenshots go in `public/uploads/zenderal/`, named by each `shot` field (empty shows a placeholder). Adding a doc to `DOCS` also requires rendering it in `ZenderalDocs.jsx`.
- **Site config** in `src/config.js`: Zenderal release stage, social links, and YouTube IDs for the home hero panel videos.

### Styling and fonts

Plain CSS: `src/index.css` (global + home) and `src/zenderal.css` (Zenderal pages), BEM-ish class names. Futura PT is loaded from Adobe Fonts using `VITE_TYPEKIT_ID`, substituted into each HTML file via `%VITE_TYPEKIT_ID%` — set locally in `.env` (gitignored) and in CI via the repo variable `vars.VITE_TYPEKIT_ID`.

### AI-generated assets (Higgsfield / Artlist connector)

Some Zenderal visuals were made with the Higgsfield (Artlist) MCP connector. Always quote the cost with `get_generation_cost` and get the user's explicit OK before generating — credits are real money.

- **Style kit "Zenderal"** (find it with `list_style_kits`): the site palette (Void `#07080a`, Night `#0d0e11`, Slate `#17181c`, Bone `#ece9e2`, Ash `#c9c5bd`, Stone `#9b968d`, Dust `#6f6a62`, Muted gold `#c9ab76`, Cold blue `#7fa7c9`), a "Treatment" guideline (dark fantasy, painterly realism, desaturated with muted gold highlights, cold blue only as an accent, keep the input image's location and lighting) and an "Exclusions" guideline (no text/logos/sigils, nothing modern, no saturated or neon colours). Pass it as `styleKitId` for any Zenderal image or video.
- **3D emblem** (`public/uploads/zenderal-emblem.glb`, ~1.8 MB): image-to-3D from the flat emblem, then hand-fixed (spiked arc moved in line with and slightly in front of the sphere, body tilted so the bottom point faces straight down) and optimised with `@gltf-transform` (simplify to ~72k tris, meshopt). sharp/libvips is broken on this machine, so textures are converted to WebP with ffmpeg instead (normal map 2048, others 1024). The model node is rotated 90° about X, so in raw vertex positions up is −Z and depth is +Y. Rendered by `src/zenderal/emblem3d.js` (three.js, lazy-loaded by `Emblem.jsx` with `live`; the flat PNG shows for reduced motion and until the model loads). The home page keeps the flat PNG — the 3D version was tried there and rejected.
- **Growing-vines logo** (`public/uploads/zenderal/logo-grow.webm`/`.mp4`): an image-to-video from an AI start frame (the Z alone, prompted to keep its exact strokes) to `logo-white.png` as the end frame. It is white on black and overlaid with `mix-blend-mode: screen`; `Logo.jsx` plays it once then swaps to the PNG, which matches the last frame. Re-encodes must keep the same crop/size as the PNG and crush the blacks to pure black.
- Check visual changes with headless `puppeteer-core` driving the system Chrome (`--use-angle=swiftshader` so WebGL works) when the Chrome extension is unavailable.

Images: photo/screenshot backgrounds are WebP (~2560px wide, quality 85 — lower bands the dark gradients); hero backgrounds live in `public/uploads/zenderal/screenshots/backgrounds/`.
